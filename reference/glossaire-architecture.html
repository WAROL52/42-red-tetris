Glossaire d'architecture

Référence rapide · liée aux leçons 0001–0006

Chaque terme est suivi d'un tag indiquant où il vit: pur = fonction pure, oob = côté serveur OOP, shared = importé par les deux côtés. Les termes du glossaire sont cohérents avec CONTEXT.md.

GameState pur
L'état minimal du terrain d'un joueur: { board, piece, over }. Entièrement sérialisable. Vient de engine.ts:29. Toute fonction du moteur le prend et le rend.
Board (ou field) pur
Grille 22×10 (Cell[][]). Rangées 0–1 = buffer invisible (spawn), rangées 2–21 = zone visible (20 rangées). Les spectres ne comptent que les 20 visibles.
FallingPiece pur
La pièce en chute: type, rotation (0–3), position (x, y), et flag grounded. Seulement présente quand une pièce est active. Chaque appel à tick()/move/rotate le met à jour.
Cell shared
Type d'une case du board: PieceKind | 'X' | null. null = vide, 'X' = garbage, sinon la lettre de la pièce (I, O, T…).
PieceKind shared
Union des 7 pièces: 'I' | 'O' | 'T' | 'S' | 'Z' | 'J' | 'L'. Défini dans protocol.ts:1.
MoveAction shared
Les 5 actions clavier: 'left' | 'right' | 'rotate' | 'down' | 'harddrop'. Mappe 1:1 avec les fonctions du moteur via applyAction.
SRS (Super Rotation System) pur
Système officiel de rotation avec wall-kicks. Utilisé par rotate() dans engine.ts. Les tables sont dans JLSTZ_KICKS et I_KICKS. Source: srs.md.
Wall-kick pur
Décalage tenté lors d'une rotation bloquée. Jusqu'à 5 essais (incluant le neutre) pour JLSTZ/I. O n'a qu'un seul essai (pas de kick).
7-bag oob
Mélange des 7 pièces (Fisher-Yates), répété. Garantit que chaque joueur reçoit la même séquence, et que toutes les pièces apparaissent au moins une fois par batch de 7.
Grounded pur
Flag sur FallingPiece. La pièce a touché un obstacle mais n'est pas encore lockée (lock en une frame). tick() la locke au tick suivant si elle reste grounded.
Lock en une frame pur
La pièce ne se fige pas au tick où elle touche — elle attend le tick suivant. Laisse une fenêtre pour glisser la pièce sous un overhang. Imposé par le sujet §5.
Top-out shared
Échec du joueur: spawn-overlap (la pièce ne rentre pas) ou lock-out (la pièce reste dans le buffer). Le client détecte, le serveur valide via Game.topOut().
Spectrum shared
Tableau de 10 nombres (hauteur par colonne, 0–20). Envoyé au serveur après lock/linesCleared/heartbeat. Le serveur le relaie aux adversaires. Calculé sur la zone visible uniquement.
Heartbeat spectre pur
Envoi périodique (toutes les 2 s) du spectre, gated: si inchangé depuis le dernier envoi, on s'abstient. Implémenté dans GameProvider.tsx:97.
Penalty (garbage) pur
Quand un joueur clear des lignes, les adversaires reçoivent n−1 rangées incassables (un trou chacune). Le serveur relaie; c'est le client qui génère les rangées et les applique localement.
Garbage row pur
Rangée de 10 cellules pleines sauf un trou (rng injectable). Jamais clearable. Générée par makeGarbageRow(rng) dans engine.ts.
applyGarbage pur
Fonction: lock forcé de la pièce active + insertion par le bas + shift de la pile vers le haut. Ce qui dépasse le buffer 22 rangées est perdu (top-out implicite).
RootState pur
L'état du store React: identité session, phase, liste joueurs, état engine, file de pièces, flags de report. Défini dans reducer.ts:14. 14 actions le transforment.
Reducer pur
Fonction (RootState, Action) → RootState. C'est la seule transition autorisée côté client. Pas de side-effect, pas de réseau. Testable avec vitest.
SocketBridge oob
Adaptateur impur qui encapsule socket.io-client. C'est le seul endroit qui touche au réseau côté client. Créé par createSocketBridge() dans socketBridge.ts. Injectable (on peut le remplacer par un mock en test).
GameProvider oob
Composant React qui monte le useReducer, le socket, et le heartbeat. C'est la racine du store; tout composant descendant accède au state via useStore().
GameSession oob
Composant « headless » (ne rend pas de DOM). Gère la boucle rAF de gravité (500 ms) et le listener clavier. Monté dans GameScreen, quand status === 'running'.
Protocol (shared) shared
Le contrat réseau: ClientToServerEvents (9 événements) + ServerToClientEvents (11 événements). C'est la seule intersection client-serveur. Tout ajout y commence ici.
Validation shared
Fonctions de garde (isValidName, isValidSpectrum…). Appelées côté serveur (obligatoire) et côté client (par confort). Protège contre les payloads malformés.
Room oob
Instance de jeu côté serveur, nommée par l'URL. Tenue par un Map<string, Game> dans socket.ts. Nettoyée quand elle devient vide.
Round oob
Un tour de jeu. Le compteur Game.round s'incrémente à chaque beginRound(). Les rounds successifs dans une même room portent des numéros consécutifs.
Host oob
Premier joueur à rejoindre la room. Seul le host peut démarrer/rejouer. Si le host part, le prochain joueur devient host (réélection).
Eliminated oob
Flag sur Player. Passe à true après topOut(). Remis à false au début de chaque round. Le joueur éliminé ne reçoit plus de pièces.
Horizon shared
Nombre de pièces à venir envoyées avec chaque distribution (valeur: HORIZON_LENGTH = 3). Affichées dans le panneau « Prochaines pièces ».
Hono oob
Framework HTTP minimal utilisé côté serveur pour servir le bundle et la SPA. Configuré dans app.ts, démarré dans index.ts sur le port 3000.
