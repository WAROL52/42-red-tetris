Garbage: makeGarbageRow + applyGarbage

Leçon 0013 · 18 min · algorithme n°7

C'est la mécanique multijoueur par excellence: quand tu élimines des lignes, tes adversaires reçoivent n−1 rangées de déchets incassables en bas de leur terrain. Deux algorithmes distincts: makeGarbageRow (fabriquer une ligne « piégée ») et applyGarbage (insérer des lignes dans un board, avec lock forcé préalable).

1. makeGarbageRow — une ligne incassable

function makeGarbageRow(rng) {
  const hole = Math.floor(rng() * COLS)   // colonne du trou
  const row = new Array(COLS).fill(true)  // 10 cellules pleines
  row[hole] = false                        // ...sauf le trou
  return row                               // boolean[10]
}
  • 9 cellules true, 1 cellule false (le trou).
  • Le trou est crucial: une ligne avec un trou ne peut jamais être complète (il faudrait remplir 10 cases pleines; le trou reste vide). Donc le garbage est « indestructible ».
  • rng() est injectable — en test on passe une fonction déterministe (() => 0.5) pour figer la colonne du trou.
Pourquoi le trou rend-il la ligne incassable ? isFullRow exige 10 cellules non-null. Une ligne de garbage a toujours un trou. Or une pièce ne peut pas combler ce trou sans laisser une case — la ligne ne sera jamais pleine, elle ne disparaîtra donc jamais. Voilà comment on fabrique un déchet « éternel ».

2. applyGarbage — deux phases en séquence

Le moment où le garbage arrive, une pièce est peut-être en train de tomber. Il faut d'abord la figer, puis insérer les rangées.

function applyGarbage(state, rows) {
  let merged = state
  if (merged.piece !== null) {
    merged = lockPiece(merged)        // phase 1 : lock forcé
  }
  if (rows.length === 0) return merged  // pas de ligne → no-op

  // phase 2 : insertion par le bas + shift vers le haut
  const board = emptyBoard()
  for (let r = 0; r + rows.length < TOTAL_ROWS; r++) {
    for (let c = 0; c < COLS; c++) {
      board[r][c] = merged.board[r + rows.length][c]   // copie décalée vers le haut
    }
  }
  for (let i = 0; i < rows.length; i++) {
    const target = TOTAL_ROWS - rows.length + i        // lignes du bas
    for (let c = 0; c < COLS; c++) {
      board[target][c] = rows[i][c] ? GARBAGE : null   // remplit avec 'X' ou trou
    }
  }
  return { ...merged, board }
}

2.1 Phase 1 — Lock forcé de la pièce en cours

Pourquoi ? Parce qu'on ne peut pas insérer des lignes par en dessous pendant qu'une pièce est en l'air — elle serait dans un monde parallèle. On la pose d'abord (lockPiece), ce qui peut elle-même créer des lignes pleines (mais on ne les clear pas ici; le clear est une étape séparée du reducer).

2.2 Phase 2 — Insertion + shift

C'est une compaction inverse de clearLines:

  1. On copie le board par le bas, décalé de rows.length vers le haut.
  2. On remplit les rows.length dernières rangées avec les lignes de garbage.

Plaçons-nous avec 1 ligne de garbage sur un board vide: 

AVANT (3 colonnes pour l'exemple):     APRÈS:
  . . .                                . 0 0   ← le contenu est poussé vers le haut
  . . .                                0 0 0
  . . .   ← on insère en bas            0 0 0
  (plancher)                            X X .   ← garbage (trou en colonne 2)
  • Tout ce qui était au-dessus monte de k cases.
  • Ce qui dépasse au-dessus du buffer est perdu (overflow) — c'est un top-out implicite pour les colonnes très pleines.

3. L'overflow — quand la pile n'a plus de place

La boucle for r < TOTAL_ROWS - rows.length copie au plus TOTAL_ROWS - rows.length rangées. Les rangées du haut du board d'origine sont tronquées (pas copiées). Donc si tu as 19 rangées pleines et qu'on insère 3 lignes de garbage, les 3 du haut débordent et disparaissent. C'est la « baseline » du top-out.

Le test engine.test.ts:308 le vérifie: avec 20 rangées pleines + 3 lignes de garbage, la colonne compte 19 + 3 = 22 blocs, et les cases du haut (board[0][4], board[1][4]) sont vides — le débordement a été tronqué proprement.

5. Le flux réseau complet

Rappelle-toi du serveur: le serveur ne stocke pas le garbage; il relaie. Le client, lui, reconstruit les rangées via makeGarbageRow et les applique via applyGarbage dans son reducer: 

// reducer.ts — 'OPPONENT_LINES'
const rows = Array.from(
  { length: lines },
  () => makeGarbageRow(rng)              // lines = count - 1
)
return { ...state, engine: applyGarbage(state.engine, rows) }

Le rng est seédé (mulberry32(seed + garbageIncoming)) pour que la position des trous soit déterministe et rejouable en test.

Mini-quiz

Combien de trous (false) contient une GarbageRow ?
B. Exactement 1 trou (colonne aléatoire) sur 10. Différence: 9 cellules true, 1 false. Le trou garantit que la ligne ne peut jamais être complète.
Que fait applyGarbage si une pièce est en train de tomber ?
B. Phase 1 : if (merged.piece !== null) merged = lockPiece(merged). On fige la pièce active avant d'insérer, sinon elle serait dans un monde parallèle quand la pile remonte.

Micro-exercice

Simule : board vide (zone visible), appeler applyGarbage(board, [row1, row2]) avec 2 lignes de garbage. Trace:

  • À quelles lignes finissent row1 et row2 ? (target = TOTAL_ROWS − 2 + i → les 2 dernières: 20 et 21.)
  • Combien de rangées vides restent au-dessus ? (20 − 2 = 18 rangées vides en haut.)
  • Que se passe-t-il si on insère 22 lignes de garbage ? (Tout l'ancien board est écrasé; seules les 22 lignes de garbage restent. C'est un top-out complet.)
