Rotation & algorithmes de matrices

Leçon 0008 · 15 min · algorithme n°2

Une pièce peut prendre 4 orientations (états 0, 1, 2, 3). Le moteur stocke chaque orientation comme une matrice booléenne (où les cases true sont les minos). L'algorithme qui passe d'une orientation à l'autre est une rotation de matrice de 90° — un classique d'algorithmique qu'on retrouve partout (images, jeux, puzzles). Cette leçon le décompose.

1. Pourquoi une matrice booléenne

La « forme » d'une pièce est abstraite et indépendante de sa position sur le board. On la décrit par une petite grille carrée où true = bloc présent:

T · état 0
SPAWN_SHAPES.T = [
  [0, 1, 0],
  [1, 1, 1],
  [0, 0, 0],
]

La pièce T spawn est une matrice 3×3. Les formes I et O sont des matrices 4×4 et 2×2 respectivement. Toutes les pièces stockent au moins SPAWN_SHAPES[type]; les 3 autres orientations sont calculées par rotation.

2. L'algorithme: rotation horaire de 90°

Le moteur définit une fonction rotateCW(shape) qui prend une matrice carrée booléenne et renvoie sa version tournée de 90° dans le sens horaire (CW). C'est la seule primitive de rotation nécessaire — les états 2 (180°) et 3 (270°) s'obtiennent en l'appliquant 2 puis 3 fois. 

function rotateCW(shape) {
  const n = shape.length
  const out = Array.from({ length: n }, () => new Array(n).fill(false))
  for (let r = 0; r < n; r++)
    for (let c = 0; c < n; c++)
      out[c][n - 1 - r] = shape[r][c]
  return out
}

2.1 La formule, expliquée

Pour une matrice carrée n×n, le point à (r, c) (ligne, colonne) part vers:

Opération Formule Intuition
Rotation horaire 90°[c][n-1-r]La colonne devient ligne inversée.
Rotation anti-horaire 90°[n-1-c][r]Variante utilisée ailleurs.

Le secret: une rotation de 90° envoie chaque cellule (r, c) vers (c, n-1-r). On inverse les rôles ligne/colonne, et on inverse la nouvelle colonne. C'est la formule à retenir, pas le raisonnement.

2.2 Démonstration sur la pièce T

état 0
→ CW →
état 1

Vérifions un point: le mino (0,1) (le « haut » du T). Avec la formule CW: r=0, c=1, n=3 → destination [c=1][n-1-r=2] = (1, 2). Et en effet, dans l'état 1, il y a un mino à (1, 2). ✓

3. Génération des 4 états — SHAPES

export const SHAPES = Object.fromEntries(
  Object.entries(SPAWN_SHAPES).map(([type, spawn]) => {
    const states = [spawn]                    // état 0 = spawn
    for (let i = 1; i < 4; i++)
      states.push(rotateCW(states[i-1]))      // 180°, 270°
    return [type, states]
  })
)
// SHAPES['T'] = [état0, état1, état2, état3]
// SHAPES['T'][state] = matrice booléenne

L'état 1 est calculé une fois, puis l'état 2 = rotateCW(état1) (donc 180°), l'état 3 = rotateCW(état2) (donc 270°). Le tout est précalculé au chargement du module — pas recalculé à chaque frame.

Invariant essentiel SHAPES[type][state] est une boolean[][] carrée dont la taille n vaut 4 (I), 3 (JLSTZ) ou 2 (O). Le nombre de minos est invariant par rotation: une pièce a toujours 4 blocs, peu importe l'état. La rotation ne change que leur position, pas leur nombre.

4. La pièce O — l'identité

La pièce O (le carré 2×2) est un cas particulier: dans le système SRS, elle ne tourne pas visuellement. rotate() le gère en ne proposant aucun kick pour O (nous verrons en leçon 0009). Sa matrice 2×2 est symétrique par rotation, donc son apparition ne change pas non plus. Le moteur la représente, mais rotate(pièce O) la laisse intacte (test engine.test.ts:152).

5. Où la rotation s'arrête — rotate()

rotate() (leçon 0009) ne fait pas que tourner la matrice: il essaie d'appliquer un décalage (kick) pour rendre la rotation valide face aux obstacles. La partie matricielle se résume à: 

const to = (p.state + 1) % 4     // état suivant (CW)
// puis, pour chaque kick candidat:
if (!collides(board, type, to, x+kick.dx, y+kick.dy))
  → position valide, on s'arrête

C'est rotateCW + SHAPES qui fournissent la forme de l'état to; les wall-kicks déplacent le point d'ancrage pour que cette forme tienne dans le board.

6. Complexité

Opération Complexité Quand
rotateCW(shape)O(n²) avec n ≤ 4une fois, au chargement (génère SHAPES)
Lecture SHAPES[type][state]O(1)à chaque frame / collision

Grâce au pré-calcul de SHAPES, la rotation pendant le jeu est O(1) pour récupérer la forme. Le calcul O(n²) n'a lieu qu'une seule fois au démarrage — un bel exemple de « payer le coût avant, pas pendant ».

Mini-quiz

Dans rotateCW, où part la cellule [r][c] ?
B. [c][n-1-r]. La colonne c devient la ligne, et la colonne cible est inversée (n-1-r). C'est la formule classique de rotation horaire 90°.
Quand rotateCW est-il appelé pendant le jeu ?
B. rotateCW est exécuté une seule fois, au chargement, pour générer états 1,2,3 dans SHAPES. Pendant le jeu, la rotation lit SHAPES[type][state] (O(1)) et n'appelle plus rotateCW.
