PRNG déterministe, Fisher-Yates et 7-bag

Leçon 0014 · 15 min · algorithmes n°8 & n°9

Le jeu a besoin de « hasard » pour la position du trou dans le garbage, et pour ordonner la 7-bag de pièces. Mais un hasard imprévisible rendrait les tests impossibles. La solution est un générateur pseudo-aléatoire déterministe (même seed → même suite) combiné à un shuffle Fisher-Yates. Cette leçon couvre les deux, dans le détail.

1. Pourquoi un PRNG déterministe plutôt que Math.random()

  • Math.random() est non-déterministe: la même « graine » ne peut pas être rejouée. Impossible de reproduire une partie buguée.
  • mulberry32(seed) produit la même suite de nombres pour le même seed. Un test peut donc injecter mulberry32(42) et prévoir exactement quels trous / quel ordre de pièces vont sortir.
  • C'est un « PRNG » (générateur pseudo-aléatoire): la suite a l'air aléatoire, mais elle est entièrement reproductible.

2. mulberry32 — le cœur du PRNG

export function mulberry32(seed) {
  let a = seed >>> 0
  return () => {
    a = (a + 0x6d2b79f5) | 0
    let t = Math.imul(a ^ (a >>> 15), 1 | a)
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296
  }
}
  • Il retourne une fonction qui, à chaque appel, renvoie un flottant dans [0, 1).
  • L'état interne a est mis à jour à chaque appel — c'est de là que vient la « suivante » valeur (déterministe tant que a et l'entrée sont identiques).
  • >>> 0, | 0, Math.imul forcent les opérations entières 32 bits — un détail crucial pour que la suite soit reproductible (le flottant JS ne suffit pas seul; on veut des entiers 32 bits stables).
Le contrat du PRNG Même seed + même nombre d'appels → même suite. C'est ce qui rend le moteur (et le shuffle) déterministe en test. Le test engine.test.ts:326 le valide: deux mulberry32(7) produisent les mêmes 100 valeurs.

3. shuffle — Fisher-Yates (ou Knuth shuffle)

function shuffle(items, rng) {
  const out = [...items]
  for (let i = out.length - 1; i > 0; i--) {
    const j = Math.floor(rng() * (i + 1))   // index aléatoire dans [0..i]
    ;[out[i], out[j]] = [out[j], out[i]]     // échange
  }
  return out
}

Algorithme de Fisher-Yates (décrit par Fisher et Yates, popularisé par Knuth). Chaque élément a une chance égale d'occuper chaque position.

3.1 Pourquoi on part du BAS et on descend vers le haut

Le bouclage part de l'indice le plus à droite et descend vers l'indice 1. À chaque étape, on tire un j uniformément dans [0..i] (indice inclus) et on échange out[i] avec out[j]. On s'arrête à i = 1 (l'échange avec l'indice 0 n'est pas nécessaire).

On descend parce qu'une fois qu'un élément est placé à l'indice i, il n'est plus jamais remué (c'est déjà sa position finale). Descendre garantit l'uniformité (chaque permutation équiprobable).

3.2 Complexité & optimalité

  • O(n) — chaque élément est touché exactement une fois.
  • C'est l'algorithme optimal de permutation: n−1 échanges, O(n) temps, O(n) espace pour la copie.

4. bag — le 7-bag Tetris

function bag(items, rng) {
  return shuffle(items, rng)   // une permutation du 7-bag
}

Le 7-bag est la règle de distribution officielle du guidetline: on mélange les 7 pièces (un « sac »), on les distribue une par une dans cet ordre, puis on prépare un nouveau sac mélangé. Résultat:

  • chaque groupe de 7 pièces contient exactement une fois chaque pièce (aucun manque),
  • l'ordre dans le groupe est aléatoire,
  • chaque pièce apparaît au moins une fois par batch — pas de sécheresse prolongée.

Côté serveur (domain.ts), BAG = ['I','O','T','S','Z','J','L'] est mélangé via un shuffle local (qui utilise Math.random côté serveur, lui le reproductible) puis poussé dans la séquence. Chaque joueur consomme la même séquence, à son propre nextIndex.

7-bag: flux

BAG = I O T S Z J L → shuffle → S J I L O T Z → distribuer un par un → quand vide, re-mélanger S J I L O T Z | J L S T Z I O | ... bag 1 bag 2 (chaque bag = les 7 pièces, 1 fois)

Client vs serveur

Client (garbage): mulberry32(seed) injecté → makeGarbageRow déterministe Serveur (pièces): Math.random() (non déterministe) → shuffle(BAG) côté serveur
Source primaire Le 7-bag est une règle officielle: voir Tetris Wiki — Random Generator. mulberry32 est un PRNG connu (originellement publié par Tommy Ettinger). Dans le code: seed.ts entier.

5. Où le seed est-il utilisé côté client

Dans reducer.ts, le rng est seédé à partir du nom de la session et d'un compteur de garbage: 

// initialState
garbageSeed: hash(room + ':' + playerName) ^ 0x9e3779b9

// à chaque ticket OPPONENT_LINES
const rng = mulberry32(state.garbageSeed + state.garbageIncoming)

Combiner seed + compteur garantit que deux players dans deux rooms ne reçoivent pas des trous identiques, tout en restant rejouables en test.

Mini-quiz

Pourquoi multiplier les PRNG déterministes plutôt que Math.random() ?
B. Un PRNG déterministe produit la même suite pour le même seed, ce qui rend les tests rejouables (exemple: engine.test.ts vérifie que deux mulberry32(7) donnent les mêmes 100 valeurs).
Combien de pièces contient chaque batch de 7-bag d'un joueur ?
A. Exactement 7 pièces par batch — chacune une fois. C'est la garantie « Random Generator » Tetris: chaque groupe de 7 contient une fois chaque pièce.

Micro-exercice

  • i=2: j = floor(0 × 3) = 0 → échange out[2] et out[0] → C B A.
  • i=1: j = floor(0 × 2) = 0 → échange out[1] et out[0] → B C A.
  • Résultat: ['B','C','A']. Essaie de le vérifier dans la console (exécute le shuffle).
