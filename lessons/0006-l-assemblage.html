2. JoinScreen — la porte d'entrée

Trois lignes importantes:

  1. sanitize(value) filtre les caractères hors [A-Za-z0-9_-] côté client (cohérent avec NAME_PATTERN côté serveur).
  2. Le bouton est désactivé tant qu'un des deux champs est vide.
  3. Au submit, on navigue vers /{room}/{name} avec URL encoding — donc on accepte les caractères spéciaux dans l'input pour les décoder dans GameScreen.

3. GameScreen — l'orchestrateur

Le composant fait deux choses dans cet ordre:

  1. Lit les useParams(), décode URL, renvoie vers / si vide.
  2. Monte le GameProvider qui contient tout le reste (y compris un composant GameSession qui ne rend rien — il gère les effets de bord).
Pattern « headless component » GameSession ne rend aucun DOM (juste return null). Son seul rôle est de brancher les useEffect qui animent le jeu (rAF de gravité + listener clavier). Cette séparation rend GameScreen purement déclaratif.

3.1 Le découpage de GameScreen

Le fichier est composé de cinq petits composants locaux, tous des fonctions qui utilisent useStore():

  • StatusBanner() — bannière contextuelle (waiting / running / finished).
  • HostControls() — bouton Démarrer / Rejouer visible uniquement pour le host.
  • Lobby() — liste des joueurs + status + contrôles host.
  • Field() — terrain central + panneau latéral « Prochaines pièces ».
  • Opponents() — rail droit avec les spectres des adversaires (grisés si éliminés).

Tous sont connectés au store, aucun n'a son propre état local sauf HostControls (qui n'en a pas besoin) et StatusBanner (idem).

4. La boucle rAF — GameSession

Voici le cœur temporel du jeu. Une seule boucle tourne tant que status === 'running': 

useEffect(() => {
  if (state.status !== 'running') return
  let frame = 0, last = performance.now(), acc = 0
  const loop = (now: number) => {
    frame = requestAnimationFrame(loop)
    acc += now - last
    last = now
    if (engineRef.current.piece === null || engineRef.current.over) return
    if (acc >= GRAVITY_MS) {       // 500 ms
      acc %= GRAVITY_MS
      dispatch({ type: 'GRAVITY_TICK' })
    }
  }
  frame = requestAnimationFrame(loop)
  return () => cancelAnimationFrame(frame)
}, [state.status, dispatch])

4.1 Pourquoi un accumulateur et pas un setInterval

  • Précision: requestAnimationFrame se synchronise avec le refresh de l'écran (~60 fps). Un setInterval(500) dérive si l'onglet est en arrière-plan.
  • Cleanup propre: cancelAnimationFrame dans le cleanup du useEffect — StrictMode-safe.
  • Déterminisme relatif: acc accumule le delta, donc un tick lent n'est jamais perdu.

5. Le clavier — focus-safe

const onKey = (event: KeyboardEvent) => {
  const action = KEY_MOVES[event.key]
  if (action === undefined) return
  event.preventDefault()
  if (statusRef.current !== 'running' || engine.over || engine.piece === null) return
  dispatch({ type: 'LOCAL_ACTION', payload: { action } })
}
window.addEventListener('keydown', onKey)

Le mapping clavier (sujet V.1.1) est: ← → = move, ↑ = rotate, ↓ = soft drop, Espace = hard drop. On utilise event.preventDefault() pour éviter le scroll de page sur Espace.

Détail d'implémentation Le prototype 07 mappait initialement ← → à la rotation (incohérence corrigée au moment de l'assemblage de la spec — cf. map.md). Ce genre de drift entre prototype et spec est normal ; le handoff final l'a corrigé.

8. Mini-quiz final

Combien de routes react-router dans App.tsx ?
B. Deux routes. La page d'accueil est JoinScreen, et tout le reste du jeu passe par GameScreen via /:room/:playerName. Pas de route « room sans player » — il faut être identifié pour jouer.
Où vit la cadence de gravité (500 ms) ?
B. GRAVITY_MS = 500 est défini en haut de GameSession.tsx, et la boucle rAF y accumule le delta avant de dispatcher GRAVITY_TICK. Le moteur ne connaît rien du temps — il reçoit juste tick() périodiquement.

9. Que faire maintenant ?

Tu as le parcours complet. Trois pistes pour continuer à apprendre:
