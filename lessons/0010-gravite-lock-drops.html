Gravité, lock en une frame et drops

Leçon 0010 · 15 min · algorithme n°4 — la machine à états du mouvement vertical

C'est le « moteur du moteur »: la séquence temporelle qui fait tomber la pièce, la pose, puis la fige. Trois algorithmes collaborent ici: une descente (tick / soft drop), une chute (hard drop), et surtout une machine à états qui gère la fameuse règle « lock en une frame ».

1. L'état grounded — la clé de tout

FallingPiece porte un booléen grounded. C'est lui qui encode « la pièce a touché le dessus de la pile mais n'est pas encore figée ». La distinction est volontaire et exigée par la spec: 

interface FallingPiece {
  type, state, x, y,
  grounded: boolean   // touché en bas ? (pas encore figé)
}
La machine à états du lock 
      [en l'air]  --tick ne peut plus descendre-->  [grounded]
      [grounded]  --tick suivant------------------>  [locké → piece=null]
Une pièce n'est jamais figée au tick où elle touche. Elle devient grounded=true, puis le tick suivant appellera lockPiece(). C'est la fenêtre d'une frame qui permet de glisser la pièce horizontalement sous un rebord.

2. tick() — la gravité pas-à-pas

function tick(state) {
  const p = state.piece
  if (p === null || state.over) return state
  if (p.grounded) {
    return lockPiece(state)                 // ① déjà au sol → lock
  }
  if (!collides(board, type, state, x, y+1)) {
    return { ...state, piece: { ...p, y: p.y + 1 } }   // ② peut descendre
  }
  return { ...state, piece: { ...p, grounded: true } } // ③ touche → grounded
}

Trois branches, dans cet ordre:

  1. Grounded → lock immédiat (on a attendu la frame précédente).
  2. Case du dessous libre → on descend d'une cellule (y+1).
  3. Case bloquée → on marque grounded=true (mais on ne lock pas encore).

Le résultat de tick() qui renvoie piece: null est le signal que la leçon 0002 décrivait: le reducer détecte ce null et enchaîne sur clearLines() puis sur l'envoi réseau.

3. softDrop() — une case, sans attendre la gravité

function softDrop(state) {
  // Identique à tick(), MAIS sans la branche "already grounded → lock".
  if (!collides(... y+1)) return { ...(y+1) }
  return { ...grounded: true }
}

softDrop est presque un tick sans lock. Il descend la pièce d'une case si possible, sinon la marque grounded. Différence clé: il n'appelle jamais lockPiece. Le « ↓ » du clavier ne fige donc pas immédiatement — il se contente de poser la pièce, la gravité s'occupe du reste au tick suivant.

4. hardDrop() — chute libre, puis lock immédiat

function hardDrop(state) {
  let y = p.y
  while (y < TOTAL_ROWS && !collides(board, type, state, x, y + 1)) {
    y++                                     // descente "simulée" en boucle
  }
  return lockPiece({ ...state, piece: { ...p, y, grounded: true } })
}
  • Une boucle while descend y jusqu'à la première case pleine.
  • Puis on appelle directement lockPiece — pas de frame d'attente. Le hard drop fige immédiatement (sauf si lockPiece est no-op).
  • Complexité: O(hauteur max) = O(22). Trivial.

5. lockPiece() — la fusion dans le board

function lockPiece(state) {
  const board = emptyBoard()                 // copie vierge
  for r, c: board[r][c] = state.board[r][c]  // reprend le terrain
  for ({ r, c } of minos(p.type, p.state)) {
    const wy = p.y + r, wx = p.x + c
    if (wy >=0 && wy<TOTAL_ROWS && wx>=0 && wx<COLS)   // bounds-check
      board[wy][wx] = p.type                 // écrit la pièce
  }
  return { board, piece: null, over: state.over }
}
  • Copie du board + écriture des minos. Immutable : l'ancien board n'est pas altéré.
  • Le bounds-check évite d'écrire hors du tableau (une pièce pouvant dépasser en haut après un kick).
  • Retourne piece: null — c'est « LA pièce est maintenant figée ».

Les minos qui dépassent en haut (dans le buffer, au-dessus de la case 0) sont ignorés (le bounds-check les saute silencieusement). Cela peut masquer une pièce semi-hors-champ — un détail important pour le top-out (leçon 0014).

6. D'où vient la cadence ? — l'accumulateur rAF

La gravité n'est pas dans engine.ts: elle est déclenchée par GameSession (leçon 0006). Un accumulateur additionne le temps écoulé (requestAnimationFrame) et dès qu'il dépasse GRAVITY_MS = 500 ms, il dispatch GRAVITY_TICK, qui appelle tick(). 

// GameSession.tsx
if (acc >= GRAVITY_MS) {
  acc %= GRAVITY_MS       // garde le reste (pas de dérive)
  dispatch({ type: 'GRAVITY_TICK' })
}

L'algorithme d'accumulation garantit qu'un ralentissement (frame à 30 fps) est compensé: on dispatch plus souvent, mais toujours à exactement 500 ms d'intervalle de temps réel. C'est ce qui rend la gravité constante, comme le demande le sujet (« vitesse constante »).

Mini-quiz

Que fait la pièce quand elle touche le haut de la pile lors d'un tick() ?
B. Elle passe en grounded=true. Le lock n'a lieu qu'au tick suivant (machine « grounded → lock »). C'est la règle du lock en une frame.
Quelle est la différence entre softDrop et tick ?
B. tick descend, marque grounded, ET appelle lockPiece quand la pièce est déjà grounded. softDrop ne fait que descendre / marquer grounded, sans jamais locker. Le lock est laissé à la gravité.

Micro-exercice

Simule à la main une pièce O tombant sur un plancher plat:

  • spawn → grounded=false.
  • Appelle tick() jusqu'à ce que la pièce soit grounded. Combien de ticks ? (dépend du plancher; quand le dessous est bloqué, ce tick pose grounded.)
  • Appelle tick() une dernière fois. Que vaut piece ? (null — lockée.)
  • Compare avec un softDrop répété sur le même plancher: quel est le comportement au dernier softDrop ? (grounded=true, mais PAS null — pas de lock.)
