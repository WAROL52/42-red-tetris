Le moteur pur (engine.ts)

Leçon 0002 · 15 min · avoir ouvert src/client/engine/engine.ts

Cette leçon ouvre le cœur du jeu: src/client/engine/engine.ts. C'est un fichier pur: pas de this, pas de DOM, pas de réseau, pas de Date.now() qui traîne. Tout est fonction qui prend un GameState et en rend un autre. On va voir pourquoi, comment, et lire les sept fonctions qui font tout le travail.

1. Pourquoi « pur » est non négociable

La pureté (même entrée → même sortie, aucun effet de bord) permet trois choses que le Tetris exige:

  • Déterminisme: on peut injecter un rng dans les tests pour rejouer une partie identique.
  • Tests triviaux: pas besoin de monter un DOM ou un socket pour vérifier qu'une rotation kick correctement.
  • Prévisibilité côté React: le reducer peut appeler ces fonctions en toute sécurité — React compare les références, et l'immutabilité rend ça gratuit.
La signature d'or 
(state: GameState, ...args) => GameState
À quelques exceptions près (clearLines renvoie aussi le nombre de lignes), toutes les fonctions du moteur ont cette forme.

2. Les constantes spatiales: 22, 20, 10

Le terrain interne fait 22 rangées sur 10 colonnes — pas 20. Pourquoi ? Parce que les pièces spawnent au-dessus du plateau visible, dans une zone tampon de 2 rangées (BUFFER_ROWS = 2).

Quand tu regardes spectrum(), il ne compte que les 20 rangées visibles — les pieces qui dépassent dans le buffer ne comptent pas dans la hauteur affichée à tes adversaires. 

export const COLS = 10
export const TOTAL_ROWS = 22   // board interne
export const VISIBLE_ROWS = 20 // ce que tu vois / ce que tu envoies
export const BUFFER_ROWS = TOTAL_ROWS - VISIBLE_ROWS  // 2

4. Le verrou en une frame — le détail subtil

Quand tick() appelle lockPiece(), la pièce ne devient pas un plateau mis à jour immédiatement. Elle devient piece: null. C'est le signal: le reducer va alors appeler clearLines() et, si des lignes ont sauté, déclencher le rapport réseau (linesCleared) et l'envoi de la pièce suivante.

1. tick() descend

piece.y += 1 (pas grounded)

2. tick() ne peut plus

piece.grounded = true (lock reporté)

3. tick() suivant

lockPiece() → piece = null

4. reducer voit null

Appelle clearLines() → { state, cleared }

5. reducer rapporte

- socket.emit('lock') - socket.emit('linesCleared')

6. serveur répond

socket.on('piece') → spawn(state, type)

C'est le « lock en une frame » imposé par le sujet: la pièce n'est jamais figée au moment où elle touche — elle attend le tick suivant. Ça laisse au joueur une chance de glisser la pièce sous un overhang (le fameux « slide under »).

5. Les SRS wall-kicks en 30 secondes

Quand tu appuies sur ↑, rotate() ne se contente pas d'essayer la nouvelle orientation in place. Elle essaie jusqu'à 5 décalages, dans cet ordre:

  1. pas de décalage,
  2. petit décalage horizontal,
  3. … vertical,
  4. … combiné.

Le premier essai qui ne collide pas gagne. Ces tables (JLSTZ_KICKS, I_KICKS dans le code) sont copiées depuis .scratch/red-tetris/research/srs.md qui les a vérifiées sur 3 sources. Tu n'as pas à les mémoriser — le code les a.

Source primaire Tetris Wiki — SRS est la référence communautaire. Pour notre implémentation, l'asset local srs.md est suffisant et plus rapide à digérer.

6. Le garbage en deux phases

Quand tu reçois penalty {lines: 3}, le reducer appelle makeGarbageRow(rng) trois fois, puis applyGarbage(). Ce dernier fait deux choses dans l'ordre:

  1. Lock forcé de la pièce active (sinon elle se retrouverait dans un monde parallèle).
  2. Insertion par le bas de k rangées pleines sauf un trou, qui poussent la pile vers le haut. Tout ce qui dépasse la rangée 0 est perdu (c'est le top-out implicite).
// engine.ts:380
export function applyGarbage(state, rows) {
  let merged = state
  if (merged.piece !== null) merged = lockPiece(merged)  // 1
  // ... puis insertion par le bas (2)
}

7. Pourquoi `applyAction` existe

applyAction(state, action) est un switch minuscule (engine.ts:403) qui mappe les 5 MoveAction à leur fonction spécialisée. Il n'existe que pour que le reducer (reducer.ts) ait un seul point d'entrée à appeler depuis le clavier. Lis-le en 10 secondes.

Mini-quiz

Pourquoi tick() ne lock pas la pièce tout de suite quand elle touche ?
B. C'est la règle « une frame » imposée par le sujet. tick() pose grounded=true, et seul le tick() suivant appelle lockPiece(). Cette fenêtre permet les glissements latéraux sous un overhang.
Combien de rangées compte spectrum() ?
B. spectrum() ne lit que les rangées BUFFER_ROWS..TOTAL_ROWS, c'est-à-dire la zone visible 20 rangées. Une pièce dans le buffer ne compte pas dans la hauteur affichée.
