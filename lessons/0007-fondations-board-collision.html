Fondations algorithmiques: board, coordonnées, collision

Leçon 0007 · 15 min · algorithme n°1 de la série

Toute la mécanique du jeu repose sur une seule question: « cette pièce, à cette position et cette rotation, touche-t-elle un mur ou un bloc déjà posé ? » La fonction qui y répond s'appelle collides(). Avant de voir les rotations, la gravité ou la détection de lignes, il faut maîtriser les trois structures qui nourrissent cette fonction: le board, la pièce, et la liste de ses minos.

1. Trois structures de données fondamentales

1.1 Le board — une grille 22×10

type Cell = PieceKind | 'X' | null
board: Cell[][]   // board[row][col]
  • Indices: board[r][c] avec r = ligne (row, 0 en haut), c = colonne (col, 0 à gauche).
  • Taille: TOTAL_ROWS = 22 lignes × COLS = 10 colonnes.
  • Rangées 0–1 = buffer invisible (où les pièces apparaissent).
  • Rangées 2–21 = zone visible (20 rangées).
  • Chaque case: null (vide), la lettre de la pièce, ou 'X' (garbage).

Pourquoi 22 et pas 20 ? Pour qu'une pièce puisse apparaître au-dessus du vol de l'écran et ensuite descendre dans la zone visible. Sans buffer, un spawn serait immédiatement un bloc déjà visible — moche et non-standard.

Board vide: buffer (r0–1) en rouge, visible (r2–21) ci-dessous
Un T spawné: minos en violet sur le board

1.2 La pièce — sa position monde

interface FallingPiece {
  type: PieceKind   // 'I' | 'O' | 'T' ... (quelle forme)
  state: Rotation   // 0 | 1 | 2 | 3  (quelle orientation)
  x: number         // colonne du bord gauche de la bounding box
  y: number         // ligne du haut de la bounding box
  grounded: boolean // a-t-elle touché en dessous ?
}

Point crucial: la pièce n'est pas stockée comme un tableau de cases absolues. Elle stocke sa forme logique (type + rotation) et un point d'ancrage (x, y). Les cases absolues sont recalculées à la volée. C'est ce recalcul qu'on appelle minos().

1.3 minos() — les coordonnées locales → monde

function minos(type, state) {
  const shape = SHAPES[type][state]        // matrice booléenne 4x4
  const out = []
  for r in 0..shape.length-1
    for c in 0..shape[r].length-1
      if shape[r][c] then out.push({ r, c })
  return out   // coordonnées LOCALES (relatives à la bounding box)
}

Pour une pièce T en état 0, minos() renvoie [{0,1},{1,0},{1,1},{1,2}] — les cellules occupées dans la bounding box 3×3, indépendamment de la position x,y.

2. L'algorithme de collision — la brique universelle

Les coordonnées monde d'un mino sont: wx = x + c (colonne absolue) et wy = y + r (ligne absolue). 

function collides(board, type, state, x, y) {
  return minos(type, state).some(({ r, c }) => {
    const wx = x + c
    const wy = y + r
    return (
      wx < 0 || wx >= COLS ||      // hors à gauche ou à droite
      wy < 0 || wy >= TOTAL_ROWS || // hors en haut ou en bas
      board[wy][wx] !== null          // case déjà occupée
    )
  })
}
  • Test de borne d'abord (hors-board), puis test d'occupation.
  • Ordre important: on vérifie les bornes AVANT d'indexer board[wy][wx], sinon board[-1] → bug hors-limites (c'est LE piège classique).
  • some() s'arrête dès qu'un mino collide — complexité O(k) avec k ≤ 4 minos.
Invariant central Une position (x, y, type, state) est valide ssi collides(...) === false. Tous les mouvements (move, rotate, tick) ne produisent que des positions valides — sinon ils sont rejetés (retour de l'état inchangé). La collision est donc la source de vérité unique de la géométrie.

3. Complexité & invariants

Fonction Complexité Limite
minos(type, state)O(4×4) = O(1)au plus 4 minos
collides(...)O(k), k ≤ 4some court-circuite
  • board est lu (jamais modifié) par collides — elle reste pure.
  • Chaque appel de minos() reconstruit la liste. Pour 4 pièces en jeu simultané, c'est négligeable. Si la perf devenait critique, on précalculerait les 28 (minos[type][state]) une fois — c'est exactement ce que fait SHAPES pour les formes.

4. Le piège n°1: les bornes avant l'indexation

Si on écrivait board[wy][wx] !== null sans vérifier wy et wx, une pièce remontant dans le buffer (spawn y=0, minos r=0 → wy=0, ok) puis au-dessus (rotation avec un kick négatif → wy=-1) lirait board[-1] → undefined, et undefined[wx] → crash. 

// TESTE LES BORNES AVANT, sinon crash:
// board[-1] === undefined  →  undefined[3]  →  TypeError
return wx<0 || wx>=COLS || wy<0 || wy>=TOTAL_ROWS || board[wy][wx]!==null

C'est pourquoi le test de borne précède le test d'occupation dans le ||. JS évalue de gauche à droite et s'arrête au premier true.

5. Visualisation tridimensionnelle de l'état

Une pièce est un point dans un espace à 3 dimensions de positions valides: (x, y, rotation). Chaque appel à move/rotate/tick propose une translation dans cet espace; si la position cible est valide, on y va; sinon on reste. collides est le « gardien » de cet espace.

Mini-quiz

Que renvoie board[-1][0] en JS ?
C. board[-1] renvoie undefined, puis undefined[0] lève une TypeError. C'est exactement pourquoi collides teste les bornes (wy < 0, wy >= TOTAL_ROWS, etc.) avant d'indexer.
Combien de minos contient une pièce T (tout type confondu) ?
B. Chaque pièce est un tétromino (4 blocs). La pièce T en état 0 a bien 4 minos: {0,1},{1,0},{1,1},{1,2}. Le maximum est donc k=4, d'où la complexité O(4) de la collision.

Micro-exercice

Trace à la main, pour une pièce I spawnée (x=3, y=0, state=0) sur un board vide:

  • Ce placement collide-t-il ? Pourquoi ? (Non: wy=1 ≥ 0 et < 22; wx dans [0,10); cases vides.)
  • Que se passe-t-il si on appelle move(s, 'left') 20 fois ? (x descend jusqu'à être bloqué par le mur; voir test engine.test.ts:127.)
