spectrum: le calcul de hauteurs par colonne

Leçon 0012 · 12 min · algorithme n°6

Le spectre est une "empreinte" compacte du terrain: 10 nombres, un par colonne, chacun égal à la hauteur de blocs empilés dans la zone visible. C'est ce que le client envoie au serveur pour que les adversaires voient ton terrain « en ombre chinoise » en temps réel — sans jamais transmettre le board complet (20×10 = 200 cases) mais seulement 10 nombres.

1. Pourquoi un spectre au lieu du board complet

  • Bande passante: 10 nombres au lieu de 200 cellules, plusieurs fois par seconde. Énorme économie réseau.
  • Confidentialité relative: on voit la hauteur, pas l'arrangement exact — c'est le « gameplay » multi.
  • Facile à relayer: le serveur stocke simplement player.spectrum (10 nombres) et le relaie. (server/domain.ts:31)

2. L'algorithme — spectrum()

function spectrum(state) {
  const heights = new Array(COLS).fill(0)     // 10 zéros
  for (let c = 0; c < COLS; c++) {             // chaque colonne
    for (let r = BUFFER_ROWS; r < TOTAL_ROWS; r++) {  // zone visible de haut en bas
      if (state.board[r][c] !== null) {
        heights[c] = TOTAL_ROWS - r            // hauteur = distance au plancher
        break                                   // premier bloc trouvé = le plus haut
      }
    }
  }
  return heights
}

Le point clé: pour chaque colonne, on parcourt les rangées visibles du haut vers le bas, et dès qu'on voit un bloc non-null, on s'arrête. La hauteur est alors TOTAL_ROWS - r :

  • TOTAL_ROWS = 22.
  • Si le premier bloc est à la rangée r = 2 (tout en haut du visible), hauteur = 22 - 2 = 20.
  • Si le premier bloc est au plancher, rangée 21 → hauteur = 22 - 21 = 1.
  • Colonne vide → jamais de break → reste à 0.

3. La formule de hauteur, de plus près

heights[c] = TOTAL_ROWS - r convertit un index de rangée (croissant vers le bas) en une hauteur (croissante vers le haut). C'est un simple renversement d'axe.

Premier bloc à la rangée → hauteur du spectre Interprétation
220pile pleine (bord du top-out)
1111pile moyenne
211un seul bloc en bas
(aucun)0 (colonne vide)

4. Le « break » — optimisation clé

Pour une colonne pleine, on lit une seule case (le premier bloc) puis on break. Sans break, on parcourrait 20 cases pour rien. C'est le même schéma « cherche le premier match » que some() dans collides.

Rappelle-toi leçon 0002: le spectre ignore le buffer. On part de BUFFER_ROWS (2), pas de 0. Donc une pièce qui dépasse en haut (dans le buffer) ne gonfle pas ta hauteur affichée — c'est voulu, tu ne « vois » pas le buffer.

5. Complexité

Cas Complexité
Board videO(10 × 20) = O(200) — parcours complet (aucun break)
Board pleinO(10 × 1) = O(10) — break immédiat
Cas moyenO(10 × hauteur moyenne)

6. Où le spectre est-il utilisé ?

  • Après un lock: bridge.emit('lock', { spectrum }).
  • Après un clear: linesCleared { count, spectrum }.
  • Heartbeat (toutes les 2 s), mais gated — on ne réémet que si le spectre a changé.

Le serveur le relaie à tous les autres joueurs via l'événement spectrum. C'est ce qui alimente le rail des SpectrumView dans GameScreen.

Source primaire La décision du spectre en temps réel (hauteur max par colonne, zone visible seule, heartbeat 2 s gated) est documentée dans docs/red-tetris-spec.md §4. L'implémentation est dans engine.ts:335.

Mini-quiz

Quel est l'indice de la première rangée visible (en code) ?
B. spectrum commence à BUFFER_ROWS = 2 et s'arrête à TOTAL_ROWS = 22 — c'est la zone visible. Il ignore les rangées 0–1 (le buffer de spawn).
Quelle valeur de spectre donne un premier bloc à la rangée 2 ?
B. heights[c] = TOTAL_ROWS - r = 22 - 2 = 20. Un bloc tout en haut de la zone visible donne une hauteur de 20 — c'est le plafond affiché.
