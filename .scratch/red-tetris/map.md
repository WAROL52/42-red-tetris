# Map — Lock the 42 Red Tetris build

## Destination

A transferable **game spec**: lock the genuinely-open decisions left on 42-red-tetris (engine rules, client state architecture, round/elimination protocol, spectrum sync, routing & screens, test strategy) so the way is clear to *build* the complete playable game — solo + multiplayer + unit tests meeting the subject's thresholds (≥70% statements/functions/lines, ≥50% branches). The build itself is executed after this map, from the spec, with no decisions left open.

## Notes

- Domain: networked multiplayer Tetris (subject v5.2), Full-Stack JS with TypeScript.
- Stack fixed: React 19 + Vite 8 SPA client; Hono + @hono/node-server + socket.io server (`src/server/`, typed events in `socket.ts`); tsconfig split `{app,node,server}.json`.
- Subject constraints: no `this` in client code; board/pieces handled by pure functions; server OOP via prototypes (Player/Piece/Game classes); no canvas, no SVG, no `<table>`; grid/flexbox only; same piece sequence for every player in a room; no data persistence; host = first joiner, re-elected on departure; join-by-URL `/<room>/<player_name>`.
- Tracker: local-markdown. Map = `.scratch/red-tetris/map.md`; tickets = `.scratch/red-tetris/issues/NN-<slug>.md`; blocking via `Blocked by: NN, NN`; claim = `Status: claimed`; resolve = append `## Answer`, `Status: resolved`, then add a context-pointer line here.
- Skills to consult per session: `/grilling` + `/domain-modeling` (decision tickets), `/prototype` (UI/protocol sketches), `/research` (external facts), then `/tdd` + `/implement` for the post-map build phase.
- Conversations happen in French.
