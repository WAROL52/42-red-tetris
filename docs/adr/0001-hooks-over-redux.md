# Client state via React hooks, not Redux

The subject recommends Redux for client state, but the 42-red-tetris client keeps its application state in a React `useReducer` store behind a `GameProvider`, with pure `engine.ts` + `reducer.ts` modules and a single impure `socketBridge.ts` face. The subject also mandates functional-first code without `this` and discourages outdated libraries; the remaining gameplay surface here is a single small reducer, so Redux' ecosystem (middleware, devtools, selectors) buys little. Hooks keep the whole state path type-inferable, React-19 idiomatic, and trivially testable via the exported pure reducer — while remaining a valid "modern JavaScript framework" choice under the subject. Revisit if the UI grows a store far beyond this game session scope.
